# 資料收集錄製程序（data_collection profile）

- 對象：現場操作人員、維護錄製系統的人
- 規格：GrassVision workspace 的 `doc/Robot_Recording_R2_Pipeline_Spec.md` 第 1、2 節（三方共用；話題、格式、R2 路徑以該文件為準）
- 程式：`src/mower_recorder`（`launch/data_collection.launch.py`、`config/data_collection.yaml`）、`deploy/docker-compose.data-collection.yaml`、`deploy/host/mower-data-collection.sh`
- 相關踩坑：P-082、P-086、P-089，以及本次新增的 P-097～P-101（相機驅動、base_footprint 基準、YAML 布林值、容器停止訊號、run_id 時區）

> 狀態：程式已在 ROS 2 Jazzy 容器以測試影像源跑過完整錄製與檢查（見文末「驗證狀態」）。真實 USB 相機、RK3568 效能、RTK 與 R2 上傳都**待實機驗證**。

---

## 0. 整體流程

```text
一次性準備：映像版本 → 安裝 compose 與 helper → 放標定檔／外參／session／R2 憑證
每次出車：  start（暫停 app 影像）→ status → smoke bag 30 秒 → check
            → 正式錄製（規格 1.7 動作）→ stop（影像還給 app）
回到 WiFi： 自動上傳（或 upload）→ verify → 推論端看到 _manifest.json 才處理
```

每個 run 的目錄（機器人 `~/.mower/bags/<robot_id>_<時間>/`；時間是容器的 UTC、字串沒有 `Z`，排序請以 `_manifest.json` 的 `started_at` 為準，P-101）：

| 路徑 | 內容 |
|---|---|
| `bag/` | telemetry：`/tf`、`/tf_static`、IMU、輪速、GNSS（`/fix`、`/gps/status`）、三個 EKF 輸出與建議話題；MCAP zstd chunk 壓縮（`zstd_fast`），512 MB 分檔 |
| `camera/` | `/camera/front/image_raw/compressed`（MJPEG 原封不動）、`camera_info`、`/tf_static`；不壓縮，256 MB 分檔 |
| `calib/` | 開錄時複製的 `camera_front.yaml`（內參）與 `extrinsics.yaml`（外參＋ `derived` 換算結果） |
| `params/` | 兩個 EKF 與 navsat_transform 的參數 |
| `run_metadata.yaml` | 規格 1.6 欄位（相機、高度、俯角、草高、天氣、刀片…） |
| `_manifest.json` | 上傳時產生；**最後**才上傳到 R2，代表整個 run 傳完 |

## 1. 一次性準備

### 1.1 映像與檔案

1. 機器人要跑**含本變更**的映像（`IMAGE_TAG` 指到新的 release 或 `main`）。新映像透過 `mower_recorder/package.xml` 帶入 gscam 與 GStreamer（v4l2src／videorate）。
2. 把 compose 與 helper 放到機器人（`install.sh` 目前還不會裝這兩個檔）：

   ```bash
   sudo install -m 644 deploy/docker-compose.data-collection.yaml /opt/mower/
   sudo install -m 755 deploy/host/mower-data-collection.sh /opt/mower/host/
   ```

3. 在機器人狀態目錄（`/opt/mower/.env` 的 `MOWER_STATE_DIR`，預設 `/home/cat/.mower`，容器內為 `/home/mower/.mower`）放：

   | 檔案 | 來源 | 說明 |
   |---|---|---|
   | `calib/camera_front.yaml` | 第 2 節標定結果 | 沒有這個檔時會用自動產生的未標定佔位檔，check 會 FAIL |
   | `calib/extrinsics.yaml` | `src/mower_recorder/config/camera_front_extrinsics.yaml` 複製後填實測值（第 3 節） | 沒有時用套件佔位值（`source: placeholder`），check 會 FAIL |
   | `data_collection_session.yaml` | `src/mower_recorder/config/data_collection_session.yaml` | 相機型號、序號、草高、天氣、刀片；每次出車前改 |
   | `r2.env` | `src/mower_recorder/config/r2.env.example` | R2 憑證，`chmod 600`，**不要**進 git、不要貼到任何文件 |

4. `.env` 可選設定：`MOWER_ROBOT_ID`（R2 路徑 `bags/<robot_id>/<run_id>/` 用；沒設就是 `mower`）、`CAMERA_DEVICE`／`CAMERA_SIZE`／`CAMERA_FPS`（沿用 app 影像的設定）、`CAMERA_RECORD_FPS`（預設 10）、`DATA_COLLECTION_UPLOAD_POLICY`（`wifi_or_dock`｜`always`｜`manual`）。

### 1.2 時間同步

- 所有 stamp 用同一個系統時鐘。出車前在主機確認 `chronyc tracking`：`Leap status : Normal`，offset 在毫秒級。
- gscam 只在串流開始時算一次「GStreamer 時鐘 → ROS 時間」的偏移：**開機後先等 chrony 同步再 start**；錄製中若發生時鐘跳動（`chronyc tracking` 看到大幅修正），重啟資料收集容器。check 的 `camera.latency` 若出現「stamp 比接收時間晚」就是這個問題。

### 1.3 相機模式、對焦與曝光

在主機（不是容器）用 `v4l2-utils`：

```bash
sudo apt install -y v4l-utils
v4l2-ctl -d /dev/video0 --list-formats-ext    # 確認 MJPG 1280x720 有 25 fps（或改 CAMERA_FPS）
v4l2-ctl -d /dev/video0 --list-ctrls          # 看控制項名稱
```

- 預設 GStreamer 管線（`camera_launch.py`）：

  ```text
  v4l2src device=/dev/video0 extra-controls="c,focus_automatic_continuous=0,focus_auto=0,exposure_dynamic_framerate=0,exposure_auto_priority=0"
    ! image/jpeg,width=1280,height=720,framerate=25/1 ! videorate drop-only=true max-rate=10
  ```

  `extra-controls` 同時寫新舊兩種核心的控制項名稱，相機沒有的會被 GStreamer 忽略（只印警告）。

- **關閉自動對焦**：`--list-ctrls` 有 `focus_automatic_continuous`（新核心）或 `focus_auto`（舊核心）時，上面的設定會把它設 0；若需要固定焦距，再加 `focus_absolute=<值>`（在 1～3 m 看清楚草葉的值），用 launch 參數 `v4l2_controls:=...` 覆寫整串。**沒有任何 focus 控制項＝定焦鏡頭**，`run_metadata` 照樣記 `autofocus: "off"`。自動對焦會改變內參（P-082），標定與錄製都要在同一個固定焦距下進行。
- **曝光**：維持自動曝光，但關掉 `exposure_dynamic_framerate`（舊名 `exposure_auto_priority`），避免暗處幀率掉到 5 fps（`mower-camera.sh` 註解記載的現象）。要手動曝光時加 `auto_exposure=1,exposure_time_absolute=<值>`，並把 session 的 `camera.exposure` 改成 `"manual"`。
- 25 fps 降到 10 Hz 時，保留的影格間隔是 80／120 ms 交錯（平均 100 ms）；`videorate drop-only` 不改寫時間戳，stamp 仍是擷取時間。要均勻 100 ms，相機模式改 20 或 30 fps。

### 1.4 相機與 app 影像的關係

- 前鏡頭平常由主機的 `mower-camera.service` 獨佔 `/dev/video0` 推給 MediaMTX（app 看的畫面）。V4L2 同時只能一個程式串流，所以資料收集期間要**暫停它**：`mower-data-collection.sh start` 會 `systemctl stop mower-camera.service`，`stop` 時再啟動。錄製期間 app 沒有影像，這是預期行為，app 的預設設定不變。
- 用 GStreamer `tee` 同時供 app 與 ROS（主機管線分一支 `image/jpeg` 給 ROS）是未來選項，但跨程序傳遞後時間戳會變成接收時間、失去擷取時間，要另外設計時鐘對應，目前**未實作、不建議用於資料收集**。

### 1.5 GNSS

- GPS 驅動是主映像裡的 `mower_gps`（Rust，`/opt/mower/.env` 的 `GPS=true`，預設開），沒有另外的 GPS 容器。它只發 `/fix`（`NavSatFix`）與 `/gps/status`（JSON 字串，約 1 Hz、狀態變化時立即補發），沒有 `ublox_gps_node` 的 NAV-PVT 話題，RTK 狀態錄在 `/gps/status`。GrassVision 規格若仍寫 `/ublox_gps_node/navpvt`，要跟著改。
- RTK 狀態：`ros2 topic echo --once /gps/status`，看 `carrier_solution`：`fixed` = RTK fixed、`float` = float、`none` = 無載波解；另有 `num_sv`、`h_acc_m`。

## 2. 相機標定（棋盤格、camera_calibration）

新相機、改變安裝（鏡頭、對焦、解析度）後都要重做。內參檔對應**錄製解析度**（1280×720），`width`／`height` 必須等於影像實際大小（P-081）。

### 2.1 棋盤格

- 印在硬板上、平整不反光；建議 A3 以上、內角點 8×6（9×7 個方格）、方格 30～40 mm。**用游標卡尺量實際方格邊長**（印表機會縮放）。
- `--size` 是**內角點**數（列×行），`--square` 單位是公尺。

### 2.2 錄一段棋盤格

在機器人上（相機固定焦距、已安裝在最終位置）：

```bash
sudo /opt/mower/host/mower-data-collection.sh start
/opt/mower/host/mower-data-collection.sh record-start
#  拿棋盤格在畫面中移動 1～2 分鐘：左右、上下、遠近（0.5～3 m）、傾斜 ±30°，
#  涵蓋畫面四角與邊緣；動作放慢，避免動態模糊
/opt/mower/host/mower-data-collection.sh record-stop
```

這個 run 沒有內參屬於正常，檢查時加 `--allow-uncalibrated`。規格 1.7 第 2 點要求每次新相機或更動安裝後的正式錄製也先錄一段棋盤格，事後可再標定。

### 2.3 在有畫面的電腦上標定

標定工具需要 GUI。可用裝有 ROS 2 Jazzy 的 Linux 電腦，或 GrassVision devcontainer（Jazzy desktop／VNC）。先把 run 的 `camera/` 複製過去（或用 `mower-bag get <run_id>` 從 R2 下載），再開三個終端：

```bash
sudo apt install -y ros-jazzy-camera-calibration ros-jazzy-image-transport-plugins

# 1) 播放影像
ros2 bag play <run>/camera --topics /camera/front/image_raw/compressed

# 2) JPEG 轉成 raw（Jazzy 的 republish 用參數指定 transport）
ros2 run image_transport republish --ros-args \
  -p in_transport:=compressed -p out_transport:=raw \
  -r in/compressed:=/camera/front/image_raw/compressed -r out:=/camera/front/image_raw

# 3) 標定（8x6 內角點、方格 0.030 m 為例）
ros2 run camera_calibration cameracalibrator --size 8x6 --square 0.030 \
  --no-service-check --max-chessboard-speed 0.25 -c camera_front \
  --ros-args -r image:=/camera/front/image_raw -p camera:=/camera/front
```

- X、Y、Size、Skew 四條進度都變綠後按 **CALIBRATE**；終端會印出 K、D 與重投影誤差。**驗收：RMS 重投影誤差 < 0.5 px（理想 < 0.3 px）**，畫面邊緣的直線看起來是直的。
- 按 **SAVE** 產生 `/tmp/calibrationdata.tar.gz`，解出其中的 `ost.yaml`，確認：
  - `image_width: 1280`、`image_height: 720`（與錄製一致）
  - `camera_name: camera_front`（不同只會有警告，但請改一致）
  - `distortion_model: plumb_bob`，`distortion_coefficients` 有 5 個
- 複製到機器人 `~/.mower/calib/camera_front.yaml`。下一次 start 時 launch log 會顯示 `intrinsics: .../calib/camera_front.yaml`，錄到的 `camera_info` 就是這份（check 會逐項比對 K）。
- 標定日期寫到 `data_collection_session.yaml` 的 `calibration_date`。

## 3. 外參量測

### 3.1 為什麼不直接量 base_footprint

這台車的 `base_footprint` 不是車上找得到的點：URDF 把它放在**驅動輪軸中點前方約 0.166 m、偏左 0.015 m、離地約 0.093 m**，但輪速里程計積分的是輪軸中點（P-086、P-098）。所以外參檔記錄的是**實體量測值**，基準點是「驅動輪（後輪）輪軸中點正下方的地面」，程式再依 URDF 換算成 TF：

```text
base_footprint → base_link → camera_front_link → camera_front_optical_frame
（URDF，robot_state_publisher） （本 profile 的 static_transform_publisher）
```

optical frame 為 x 右、y 下、z 前（P-009）；原地旋轉時若發現相機位置在世界座標裡平移，代表里程計原點與 URDF 不一致，離線端可用檔案裡的原始量測值重算。

### 3.2 量測項目

| 欄位（`extrinsics.yaml`） | 量法 | 單位 |
|---|---|---|
| `reference.axle_height_m` | 驅動輪輪軸中心到地面（約等於輪半徑 0.09） | m |
| `camera.forward_of_axle_m` | 鏡頭光心到驅動輪軸線的水平距離，向前為正（鉛垂線投影到地面後用捲尺量） | m |
| `camera.left_of_center_m` | 鏡頭光心偏離兩驅動輪中線的距離，向左為正 | m |
| `camera.height_m` | 鏡頭光心到**地面（土面，不是草冠）**，在平坦硬地面上量 | m |
| `camera.pitch_deg` | 俯角，向下為正：手機水平儀或角度尺貼在與光軸平行的相機機身上緣／背板（背板要加 90°） | 度 |
| `camera.roll_deg` | 左右傾斜，右側向下為正（通常 0） | 度 |
| `camera.yaw_deg` | 相機相對車頭的偏航，向左為正（通常 0） | 度 |

- 光心位置不確定時，取鏡頭玻璃中心；誤差約 1 cm，可接受。
- 距離量兩次取平均，記在 `method`（例如「捲尺＋鉛垂線；手機水平儀量俯角兩次平均」），填 `date`、`measured_by`，並把 `source` 改成 `measured`。
- 改過安裝就要重量；舊值留在舊 run 的 `calib/` 裡，不會被覆寫。

### 3.3 驗證

1. `start` 後看 launch log：`base_footprint -> optical: xyz=[...] rpy_deg=[...]`，z 應約等於 `height_m − 0.093`，rpy 約為 `(-90 − 俯角, 0, -90)`。
2. `check` 會檢查 `/tf_static` 的完整鏈、光軸朝前，以及 TF 與 `calib/extrinsics.yaml` 的 `derived` 一致。
3. Foxglove 3D panel 開 `camera/` 的 mcap：相機視錐應該朝前下方、底緣接近地面。
4. 離線：規格 1.7 第 5 點錄的平坦硬地面，可用地面平面擬合反推俯角與高度（P-070、P-084），誤差大於 1°／2 cm 時回頭重量。

## 4. 每次出車：錄製程序（規格 1.7）

### 4.1 出車前

1. 改 `data_collection_session.yaml`：草高、天氣、`blade: "off"`、`heading_calibration: "pending"`、notes。字串一律加引號（`"off"`，P-099）。單次 run 的差異也可以在啟動時用 `run_info:="{weather: cloudy}"`。
2. 刀片關閉（前幾次錄製都保持關閉）、電量足夠、儲存空間：`df -h ~/.mower/bags`（影像每小時約 4～7 GB，要寫在 eMMC／SSD，不要寫 microSD）。
3. 主系統（`mower.service`，`GPS=true`）已在跑，RTK fixed（1.5 節）。
4. 啟動資料收集：

   ```bash
   sudo /opt/mower/host/mower-data-collection.sh start     # 會暫停 mower-camera.service 與自動更新
   /opt/mower/host/mower-data-collection.sh status         # 影像約 10 Hz、recording=false
   ```

### 4.2 smoke bag（每次正式錄製前）

```bash
/opt/mower/host/mower-data-collection.sh smoke 30
```

錄 30 秒後自動停止並執行 `mower-check-run`。**有 FAIL 就先處理，不要開始正式錄製**（第 5 節）。

### 4.3 正式錄製

```bash
/opt/mower/host/mower-data-collection.sh record-start      # 回覆「開始錄製 run=...」後才開始動作
```

回覆會晚幾秒（先存參數與 metadata）。依序進行：

1. 開錄後**靜止 5 秒**。
2. 新相機或更動安裝後：錄一段棋盤格（2.2 節的動作）。
3. **原地左轉一圈、右轉一圈**（估相機與 IMU 的時間偏移）。
4. **直線來回 10～20 m**（估 IMU 航向偏差，P-086）；做完把 session 的 `heading_calibration` 改成 `"straight_line_done"`（或下次 run 用 `run_info` 帶入）。
5. 在 **1、3、5 m** 擺已知尺寸的標記物；**至少錄一段平坦硬地面**。
6. 作業路線（刀片保持關閉）。
7. 結束前靜止 3～5 秒，然後：

   ```bash
   /opt/mower/host/mower-data-collection.sh record-stop     # 回覆「已停止並封存: full, camera」
   /opt/mower/host/mower-data-collection.sh check           # 檢查剛才的 run
   ```

- 單一 run 建議 20～30 分鐘以內（上傳與重傳比較快）。
- **一定要用 `record-stop`（或 helper 的 `stop`）結束錄製**。直接 `docker stop`、拔電或 kill 會讓 mcap 沒有封存：沒有 `metadata.yaml`，zstd telemetry 還在記憶體裡的 chunk 會整段遺失（P-100）。

### 4.4 收工

```bash
sudo /opt/mower/host/mower-data-collection.sh stop          # 停止錄製與容器，影像還給 app，恢復自動更新
```

## 5. smoke bag／run 檢查（mower-check-run）

`mower-check-run <run_dir>` 是純 Python（PyYAML；zstandard 可選），機器人容器內用 helper 的 `check`，在 Mac 或推論端可直接執行單檔：

```bash
python3 src/mower_recorder/mower_recorder/check_run.py <run_dir> [--json out.json]
```

| 檢查 | 內容 | 常見 FAIL 與處理 |
|---|---|---|
| `bag.metadata`／`bag.mcap`／`bag.counts` | 每個 bag 有 `metadata.yaml`、mcap 有 footer、訊息數一致 | 錄製沒正常結束：`ros2 bag reindex <run>/bag -s mcap` 重建 metadata；截斷的 mcap 另用 mcap CLI `mcap recover` |
| `bag.compression` | 不可是 rosbag2 逐訊息壓縮 | 用錯 profile（常駐 profile 仍是逐訊息壓縮，P-089） |
| `topic[...]` | 規格 1.1 必要話題存在、型別正確、頻率：影像約 10 Hz、IMU ≥ 8、EKF ≥ 15、`/fix` ≥ 3、`/gps/status` ≥ 0.8 | `/fix`／`/gps/status` 缺：`.env` 的 `GPS=false` 或接收機沒接上（`/dev/gps_rtk`）；影像頻率低：曝光太長（1.3 節） |
| `camera.jpeg`／`camera.size`／`camera.info_size` | JPEG 完整、尺寸一致、`camera_info` 與影像同尺寸（P-081） | 內參檔解析度與錄製模式不同 |
| `camera.pairing` | 影像與 `camera_info` 的 stamp 1:1 | 頭尾各 2 秒內少一兩則可接受 |
| `camera.intrinsics`／`calib.intrinsics_file` | K 已標定、與 `calib/camera_front.yaml` 相同 | 尚未標定（錄棋盤格時加 `--allow-uncalibrated`） |
| `camera.latency` | 接收時間 − stamp 的中位數（USB 相機通常數十 ms） | 負值：時鐘在相機啟動後被調整（1.2 節）；小於 3 ms：stamp 是接收時間 |
| `tf_static.chain`／`tf_static.extrinsics` | 完整相機鏈、光軸朝前、與外參檔一致 | 主系統沒在跑（缺 `base_footprint → base_link`）；外參檔不合法 |
| `tf[...]`／`tf.parents` | `odom → base_footprint`、`map → odom` 存在；沒有 frame 有兩個 parent | 另外啟動了 `mower_base.launch.py`（P-086 第 6 點） |
| `stamp[...]` | header.stamp 嚴格遞增、不為 0 | 重複影格或時鐘倒退 |
| `calib.*`／`metadata.fields` | 標定檔存在、外參不是佔位值、規格 1.6 欄位齊全 | 外參 `source: placeholder`；session 還有 `<型號>` |
| `manifest` | 有 `_manifest.json` 時核對大小與 sha256 | 上傳後又改了檔案 |

結束碼：0 = 沒有 FAIL，1 = 有 FAIL（`--strict` 時 WARN 也算）。

## 6. 上傳與確認

1. **自動**：資料收集容器裡的 `bag_store` 在 `wlan0` 有 IPv4（或 dock）時，每 30 秒把還沒上傳的 run 傳到 `r2://<bucket>/<R2_PREFIX>/<robot_id>/<run_id>/`。容器要持續開著才會上傳。
2. **手動（容器已停止也可）**：

   ```bash
   /opt/mower/host/mower-data-collection.sh upload        # = mower-bag upload --all
   ```

3. 上傳順序：先傳所有檔案（`calib/`、`run_metadata.yaml`、`bag/`、`camera/`…），每傳完一個就記在 run 目錄的 `.upload_state.json`；全部確認（HEAD 核對大小）後，**最後**才寫本機 `_manifest.json` 並上傳，再建立 `.uploaded`。
4. **中斷重傳**：WiFi 斷線或容器重啟後再執行一次（或等下一個自動週期），已上傳且未變更的檔案會跳過，只補傳缺的；`_manifest.json` 仍然最後才上傳。
5. 錄製沒有正常結束（bag 沒有 `metadata.yaml`）的 run **不會上傳**，原因會出現在 `/mower_recorder/bags` 的 `upload_error`；先 reindex（第 5 節）。
6. **確認**（任何有 R2 讀取權限的電腦，憑證放 `~/.config/mower/r2.env`；沒有 ROS 時在 repo 根目錄執行 `pip install boto3 pyyaml` 後改用 `PYTHONPATH=src/mower_recorder python3 -m mower_recorder.cli ...`）：

   ```bash
   mower-bag ls                 # MANIFEST 欄：done = 上傳完成；incomplete = 還在傳或中斷
   mower-bag verify <run_id>    # 下載 _manifest.json，逐一核對 R2 物件大小
   ```

   推論 worker 與 Mac app 只處理有 `_manifest.json` 的 run（規格 2.1），下載後再驗 sha256。
7. 從 app 刪除 run 時，R2 上會先刪 `_manifest.json` 再刪其他物件，避免半刪除的 run 被當成完整的。

## 7. 疑難排解

| 症狀 | 處理 |
|---|---|
| `start` 等不到影像話題 | `docker compose -f /opt/mower/docker-compose.data-collection.yaml logs data_collection`：`Device '/dev/video0' is busy` → `mower-camera.service` 還在跑；`no element "v4l2src"` → 映像太舊（1.1 節）；`not-negotiated` → 相機不支援該解析度／幀率 |
| 容器內沒有 `/dev/video0` 權限 | 主機 `ls -l /dev/video0` 的 group 與容器 `video` 的 GID 不同時，在 compose 的 `group_add` 改成數字 GID |
| 影像約 5 fps | 自動曝光在暗處拉長曝光；確認 `exposure_dynamic_framerate`／`exposure_auto_priority` 已關閉 |
| launch 直接失敗、提到 extrinsics | `extrinsics.yaml` 欄位錯誤或超出範圍（俯角 −5～80°、高度 0.05～2.5 m） |
| `/gps/status` 沒錄到 | 1.5 節；`GPS=true`、`ros2 topic list` 有 `/gps/status`，主系統 log 有 `gps` 節點的 `fix: type ...` |
| `record-start` 很久才回覆 | 開錄前會 dump 三個節點的參數（每個約 1～2 秒）；節點不存在時會失敗但不影響錄製 |
| 停止後 bag 沒有 `metadata.yaml` | 容器被 SIGTERM／SIGKILL 停掉（P-100）。compose 已設 `stop_signal: SIGINT`，仍請先 `record-stop` |
